Vista General del Sistema

Sistema web para generación automatizada de PDFs de publicación en Gaceta de Propiedad Intelectual del Ecuador.

🎯 Propósito

Generar PDFs de publicación de patentes para la Gaceta de Propiedad Intelectual, extrayendo datos de la BD iepi_formularios, descargando reivindicaciones/dibujos y componiendo documentos A4 con layout institucional SENADI.

⚡ Capacidades

  • Generación individual por código
  • Ingreso manual de datos
  • Generación por lotes continuos
  • Lote "Datos con hojas en blanco"
  • Verificación de publicación previa
  • Persistencia de lotes en BD

🏗️ Stack Tecnológico

RuntimeWildFly 19 / Java EE 8
UIJSF 2.3 + PrimeFaces 8
PDFPDFBox 2.0.29 + OpenPDF 1.3.43
BDMySQL 5.x (JDBC directo)
AuthLDAP (Active Directory) + filtro servlet

Estructura de Módulos

6 paquetes Java + 1 paquete de seguridad externo. Todos bajo ec.gob.senadi.pdftool (excepto seguridad LDAP).

🔒 Seguridad

ec.gaceta.security + ec.gob.senadi.pdftool.web

  • AuthBean.java — CDI @SessionScoped, login/logout, roles ADMIN/USER
  • AuthFilter.java — Servlet Filter, protege *.xhtml excepto login
  • Grupos AD: SC_PatgacetaAdmin, SC_Patgaceta
  • DEV_MODE: credenciales locales admin/admin, user/user

📦 Modelo (DTOs)

ec.gob.senadi.pdftool.model
  • PatentData — DTO principal: datos patente + enum PatentType
  • PatentData.PersonaPatente — Solicitante/inventor/representante
  • PatentData.Prioridad — País + número + fecha prioridad
  • BatchPatentItem — Item mínimo para lotes (UI + búsqueda)
  • GazettePendingRecord — Registro pendiente de publicación
  • GazettePublicationInfo — Info de publicación previa

⚙️ Servicios de Datos

ec.gob.senadi.pdftool.service
  • DatabaseSearchService — JDBC a iepi_formularios + iepi_sipigaceta
  •   → search(), loadPatentData(), findGazettePublication()

  •   → downloadFileFromServer() via LOAD_FILE()
  • SqlDumpSearchService — Búsqueda en dump SQL (base.sql)

Configuración clave de web.xml:
  • Multipart: Habilitado en el FacesServlet para subida de PDFs con PrimeFaces <p:fileUpload>. Límite 50 MB por archivo, 100 MB total por request.
  • Uploader nativo: primefaces.UPLOADER=native usa la API Servlet 3.0+ (no requiere Apache Commons FileUpload).
  • Tema: nova-light — tema claro profesional de PrimeFaces.
  • Estado cliente: STATE_SAVING_METHOD=client serializa el view state en el HTML, previniendo ViewExpiredException al invalidar sesión en logout.
  • AuthFilter: Intercepta todas las peticiones *.xhtml. Excluye login.xhtml y recursos JSF. Redirige a login si no hay sesión.

bean-discovery-mode="all":
  • CDI escanea todas las clases del WAR como beans manejados.
  • Permite inyección (@Inject) de servicios como DatabaseSearchService y PdfProcessingService sin declararlos explícitamente.
  • @SessionScoped, @ApplicationScoped, @Named funcionan automáticamente.
  • Alternativa: annotated (solo escanea clases con anotaciones CDI) — se usa all por simplicidad.

Arquitectura de despliegue:
  • Tipo: WAR empaquetado (no exploded) — un solo archivo .war
  • Servidor: WildFly 19.1.0.Final (Java EE 8 Full Profile)
  • Hot deploy: WildFly monitorea standalone/deployments/ — al detectar un .war nuevo lo despliega automáticamente
  • Marker files: .deployed (activo), .failed (error), .dodeploy (trigger manual)
  • Context path: /senadi-pdf-web (derivado del nombre del WAR)
  • Puerto: 8080 (HTTP) — configurable en standalone.xml

1 Arquitectura del Compositor por Lote

El sistema genera un único PDF continuo que contiene N patentes sin desperdiciar páginas. Cada patente fluye inmediatamente después de la anterior, con separadores visuales entre secciones.

3 Gestión del Lote en PdfProcessorBean

El bean @SessionScoped mantiene la lista lotePat: List<BatchPatentItem> y orquesta todo el ciclo de vida del lote:

Agregar al Lote

  • agregarAlLote() — construye BatchPatentItem desde PatentData
  • Verifica duplicados vía equals() por applicationNumber
  • Consulta publicación previa en gaceta vía findGazettePublication()
  • Si ya fue publicada → muestra diálogo dlgConfirmPublicado
  • confirmarAgregarAlLote() / cancelarAgregarAlLote()
  • Persiste en BD: savePendingBatchItem(appNum, fecha) con tabloid_status=1

Operaciones del Lote

  • moverArriba(i) / moverAbajo(i) — reordenar patentes
  • confirmarEliminarDelLote(i) — eliminar con confirmación
  • vaciarLote() — limpia lista + deleteAllPendingBatchItems() en BD
  • recargarLoteDesdeBD() — vía @PostConstruct, recarga pendientes al iniciar sesión
  • generarPdfLote() — genera el PDF unificado
  • generarPdfLoteBlank() — variante con hojas en blanco

4 Persistencia de Lotes en Base de Datos

Los ítems del lote se persisten en la tabla patent_forms de la BD iepi_sipigaceta usando el campo tabloid_status:

-- Agregar al lote (marcar como pendiente) UPDATE iepi_sipigaceta.patent_forms SET tabloid_status = '1' WHERE file_name LIKE '%{applicationNumber}%'; -- Cargar pendientes al iniciar sesión (@PostConstruct) SELECT file_name FROM iepi_sipigaceta.patent_forms WHERE tabloid_status = '1'; -- Vaciar lote completo UPDATE iepi_sipigaceta.patent_forms SET tabloid_status = '0' WHERE tabloid_status = '1';

Ciclo de vida del tabloid_status:

ValorEstadoDescripción
0 / NULLLibreNo está en ningún lote pendiente
1PendienteAgregada al lote, esperando generación
PPublicadaYa fue publicada en una gaceta

5 Almacén de Pendientes de Gaceta (GazettePendingStore)

Complemento @ApplicationScoped que mantiene en memoria una lista compartida de todos los registros pendientes de publicación:

Métodos principales

  • addBatch(user, items, dataList) — registra ítems como pendientes, evita duplicados
  • getPendingItems() — todos los ítems (tabla admin)
  • getUnsavedItems() — solo los no persistidos en BD
  • markSaved(appNum) — marca como guardado en BD
  • removeSaved() — limpia ítems ya guardados
  • getUnsavedCount() — contador para badge UI

Características técnicas

  • Scope: @ApplicationScoped — compartido por todos los usuarios
  • Thread safety: Collections.synchronizedList + bloques synchronized
  • Duplicados: Verificación por applicationNumber (case-insensitive)
  • Timestamp: yyyy-MM-dd HH:mm vía LocalDateTime
  • CDI Name: #{pendingStore}
  • Inject: Inyectable en cualquier bean vía @Inject
